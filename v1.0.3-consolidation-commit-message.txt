Merge inline-ternary + line-number-tracking; reorganize tests; cleanup

Harmonizes two previously separate feature branches
(feature/inline-ternary-conditional and feature/error-line-numbers,
the latter already built on top of the former) into a single change
against current main, then folds in a repository cleanup pass on top.

New language features
- Inline conditionals: `<value> kama <condition> sivyo <value>`, a
  real ternary expression usable anywhere a value is expected.

Improvements
- Runtime errors now quote the source line they happened on
  (`Mstari <n>:`), threaded through from the lexer's token line
  numbers into every parsed statement and read back by Errors.py.

Repository cleanup
- Moved all scattered *.ham test scripts into a single tests/ folder.
- Removed Console.py, Stack.py, Symbols.py - confirmed unused and
  unimported anywhere.
- Removed dead module-level scaffolding in StatementParser.py left
  over from before the SymbolTable-based design (an unused
  'variables' dict, an unused 'context' dict, write-only
  'definition_flag'/'call_flag' globals, the never-called
  breadcrumb() helper, and unused StatementParser class attributes).
- Removed the unused ArgumentConstructorExpression stub from
  ExpressionParser.py.
- Added exhaustive, beginner-oriented comments throughout
  ExpressionParser.py and Objects.py, plus targeted additions to
  Errors.py and StatementParser.py.

CHANGELOG.md and README.md updated to document all of the above as
part of the v1.0.3 release. Verified with the full functional test
battery (main.py's embedded demo plus every tests/*.ham script) -
behavior unchanged from before the cleanup, aside from the intended
new ternary/line-number output.
