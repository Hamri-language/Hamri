Title: Merge inline ternary + line-number tracking into v1.0.3; reorganize tests; cleanup

## What this PR does

This harmonizes two feature branches that had been developed in parallel
off slightly different points in history, and folds a repository
cleanup pass on top:

- `feature/inline-ternary-conditional` — the real inline conditional
  expression (`<value> kama <condition> sivyo <value>`).
- `feature/error-line-numbers` — already built on top of the ternary
  branch — adds `Mstari <n>:` (source line) prefixes to every runtime
  error message.

Both branches had drifted behind `main` (which has since picked up the
`jaza`-into-property fix, the `sawa` → `sawa na` rename, and the
Notepad "clear console on Run" fix via PRs #11/#12), so this PR is a
fresh integration of everything against current `main`, not a plain
fast-forward merge. Only `CHANGELOG.md` had a real merge conflict
(both sides added an `## Unreleased` section); it's resolved by folding
every entry — old and new — directly into the `v1.0.3` section, since
none of this has shipped yet.

On top of that integration, this PR also does the repository
housekeeping requested alongside it:

### Test reorganization
- All four scattered `*.ham` test scripts (`test_v1_0_3.ham`,
  `ternary_test.ham`, `line_number_test.ham`,
  `line_number_full_test.ham`) now live in a single `tests/` folder
  instead of loose in the repo root.

### Dead code removal
- Removed `Console.py`, `Stack.py`, `Symbols.py` — confirmed via a
  repo-wide search that none are imported anywhere. (`Symbols.py` in
  particular defined its own unrelated `SymbolTable`/`Scope` classes
  that only ever collided confusingly in name with the real,
  actively-used `SymbolTable.py`.)
- Removed dead module-level state in `StatementParser.py` left over
  from before the `SymbolTable`-based design took over: an unused
  `variables` dict, an unused `context` dict, `definition_flag` and
  `call_flag` globals that were set but never actually read anywhere,
  the never-called `breadcrumb()` helper, and unused `StatementParser`
  class attributes (`compound_statement`/`context`/`prev_context`/
  `function_flag`).
- Removed the unused `ArgumentConstructorExpression` stub from
  `ExpressionParser.py` (defined, never referenced).

None of this changes any observable behavior — verified by running the
full functional test battery before and after and diffing the output.

### Comments
- Added exhaustive, beginner-oriented comments to `ExpressionParser.py`
  and `Objects.py` (previously the two least-commented files in the
  codebase), explaining both the Hamri-level semantics of each
  expression class and the underlying Python idioms in play.
- Added targeted comments to `Errors.py` (the exception-dispatch
  pattern) and `StatementParser.py` (a few under-commented helper
  methods), on top of what the line-number-tracking work already
  documented there.

`README.md` and `CHANGELOG.md` are updated throughout to reflect all of
the above.

## Testing

- `python3 -m py_compile *.py` — clean compile.
- `python3 main.py` — embedded demo script output unchanged.
- `python3 main.py tests/ternary_test.ham` — inline ternary evaluates
  correctly, including the chained else-if form.
- `python3 main.py tests/line_number_test.ham` and
  `tests/line_number_full_test.ham` — errors correctly quote the line
  they occurred on.
- `tests/test_v1_0_3.ham` (piped stdin for the two `jaza` prompts) —
  full run through classes, loops, lists, and `kabisa`/`sawa na`
  unaffected.

## Notes for the reviewer

This PR does not include the `v1.0.3` tag move — that's a separate,
one-line follow-up once this is merged (moving the existing `v1.0.3`
tag forward to the new tip of `main`), since the tag currently points
at a commit from before PRs #11/#12 even landed.
